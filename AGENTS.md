# Collaboration rules

- Treat the current source and package manifests as the source of truth. Keep README as the entry point, current behavior in `docs/`, and runtime skill instructions in `skills/`.
- Keep one authoritative description for each configuration or tool contract; link to it from other documents. Do not move runtime `SKILL.md` files into `docs/`.
- `release/jenkins/` is generated by `pnpm build`. Edit its inputs, rebuild, and verify the output file list; do not patch the package directly.
- Never commit Jenkins URLs containing credentials, API tokens, private build logs or generated local config files. Use placeholders in examples.
- For code changes, run `pnpm test` and `git diff --check`. Distinguish mock tests from a live Jenkins or Codex installation check.
- In a repository with `.codegraph/`, use CodeGraph before text search or file reads when locating or understanding code. Do not create an index unless asked.
- When network access fails, inspect current direct/proxy routes, local proxy and hosts configuration before retrying. Keep internal addresses out of a public proxy path.
